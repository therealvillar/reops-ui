# Implementation audit (before changes)

- Starting branch/commit: `main` at `8e2f2dd21ac916d679b60fb3825554348512f08a`; clean worktree. Work proceeds on `feature/property-map-enrichment`.
- Baseline: `npm test` passed 50/50; `npm run check` passed after `npm ci` restored the lockfile's dependencies. No production D1 mutations or deploy were performed.
- `wrangler.jsonc` deploys the Vite `dist` assets through `worker/index.ts` (`reops-ui`), with `DB` bound to the existing `reops` database (`7a1cc07b-395b-4bf2-8331-ddcd740e183d`), a minute Cron, Access, and same-origin mutation checks. Preview bindings also point at that database; previews must not be used for migration tests. Migrations `0001`–`0006` are already in source; the live migration ledger was not queried here.
- `properties.data` is JSON with an immutable UUID, owner, creator, version and history in relational columns. The API authenticates every request, restricts reads to owners/members and writes to owners/editors. Property saves use a version guard; notes, reminders, notifications, AI opt-in and saved views have their own D1 tables.
- The frontend's map uses Leaflet with a direct OSM public tile URL, a 490px map, a projected-grid cluster layer and an `img-src` CSP restricted to OSM. Tile errors replace a status label, but no provider configuration exists. Existing point data comes from the saved coordinates in property JSON; missing/invalid coordinates are not rendered. The default saved-view shape includes `layers: ['properties']`, but a valid saved view with `layers: []` deliberately hides properties. The empty state describes this but has no one-click recovery.
- New/edit forms require a `name`, and list, board, map, layer API and AI defaults use it. Census lookup already uses server requests, a bounded response, timeout, D1 cache, signed 15-minute candidate tokens and `system:geocoder` backfill. Create currently saves unmatched, ambiguous and upstream-failed addresses as unlocated without explicit draft consent.
- `worker/area.ts` queries seven Philadelphia CARTO tables for **nearby** records; Montgomery parcels are enabled, Bucks and Delaware ingestion are disabled pending permissions. These are not exact-property matches and are not persisted. External CARTO hosts do not resolve from this workspace, so live schemas and production access/tiles cannot be verified here. No source-specific exact-join schema was established for permits, transfers, violations, or other county feeds.
- Existing tests cover authentication, ownership, CRM, Census tokens/cache/backfill, saved views, AI and mocked nearby data. Gaps: real basemap browser rendering, saved-view legacy recovery, explicit unlocated-draft consent, persistent exact-record matches/jobs, and migration upgrades. The production database and its previously reported user records must remain untouched until a backed-up, separately authorized release.
